# UI Coding Standards

This document outlines the coding standards and best practices for all UI development in the Lifting Diary Course application.

## ⚠️ CRITICAL RULES

### 1. Component Library: shadcn/ui ONLY
**ABSOLUTELY NO custom UI components should be created.**

- **ONLY use shadcn/ui components** for all UI elements
- **NEVER create custom components** for buttons, inputs, cards, dialogs, etc.
- If a UI element is needed, **first check** if shadcn/ui provides it
- Install shadcn/ui components as needed via CLI: `npx shadcn@latest add <component-name>`
- shadcn/ui documentation: https://ui.shadcn.com/

### 2. Date Formatting: date-fns ONLY
**All date formatting MUST use date-fns with the specified format.**

- **ONLY use date-fns** for date formatting and manipulation
- **NEVER use** native `.toLocaleDateString()`, `.toLocaleTimeString()`, or manual date formatting
- **Required format**: `do MMM yyyy` (e.g., "1st Sep 2025", "2nd Aug 2025", "3rd Jan 2026", "4th Jun 2024")
- Import: `import { format } from "date-fns";`
- Usage: `format(date, "do MMM yyyy")`

**Example:**
```tsx
import { format } from "date-fns";

// ✅ CORRECT
const formattedDate = format(new Date(), "do MMM yyyy"); // "1st Sep 2025"

// ❌ WRONG - Do not use native methods
const formattedDate = date.toLocaleDateString('en-US', { ... });
```

## Component Architecture

### Server Components First
- **Default to Server Components**: All components should be Server Components unless client-side interactivity is required
- **Use `"use client"` directive sparingly**: Only add when you need:
  - React hooks (`useState`, `useEffect`, etc.)
  - Event handlers (`onClick`, `onChange`, etc.)
  - Browser APIs
  - Third-party libraries that require client-side execution

**Example:**
```tsx
// Server Component (default - no directive needed)
export default function WorkoutList({ workouts }: WorkoutListProps) {
  return <div>...</div>;
}

// Client Component (explicit directive required)
"use client";

import { useState } from "react";

export function DatePicker({ selectedDate, onDateChange }: DatePickerProps) {
  // Uses hooks, needs "use client"
}
```

### Component Organization
- **Pages**: Located in `src/app/` following Next.js App Router conventions
- **shadcn/ui Components**: Located in `src/components/ui/` (auto-generated by shadcn CLI)
- **Custom Logic Components**: Located in `src/components/` (for business logic only, NOT UI elements)
- **One component per file**: Each component should have its own file
- **Co-locate related code**: Keep types, utilities, and components together when they're tightly coupled

## Date Formatting with date-fns

### Installation
Ensure date-fns is installed:
```bash
npm install date-fns
```

### Standard Format
**All dates MUST be formatted as: `do MMM yyyy`**

This produces:
- 1st Sep 2025
- 2nd Aug 2025
- 3rd Jan 2026
- 4th Jun 2024

### Basic Usage
```tsx
import { format } from "date-fns";

// Format a date
const displayDate = format(new Date(), "do MMM yyyy");
// Result: "1st Sep 2025"

// Format from string
const displayDate = format(new Date("2025-09-01"), "do MMM yyyy");
// Result: "1st Sep 2025"

// Format from timestamp
const displayDate = format(1725148800000, "do MMM yyyy");
// Result: "1st Sep 2025"
```

### Common date-fns Functions

**Formatting:**
```tsx
import { format } from "date-fns";

// Display date (REQUIRED FORMAT)
format(date, "do MMM yyyy"); // "1st Sep 2025"

// Time (if needed for specific cases)
format(date, "HH:mm"); // "14:30"
format(date, "h:mm a"); // "2:30 PM"

// Date and time together
format(date, "do MMM yyyy 'at' h:mm a"); // "1st Sep 2025 at 2:30 PM"
```

**Date Manipulation:**
```tsx
import { addDays, subDays, addMonths, subMonths, startOfDay, endOfDay } from "date-fns";

// Add/subtract days
const tomorrow = addDays(new Date(), 1);
const yesterday = subDays(new Date(), 1);

// Add/subtract months
const nextMonth = addMonths(new Date(), 1);
const lastMonth = subMonths(new Date(), 1);

// Start/end of day (useful for date comparisons)
const dayStart = startOfDay(new Date());
const dayEnd = endOfDay(new Date());
```

**Date Comparison:**
```tsx
import { isBefore, isAfter, isSameDay, isToday, isYesterday } from "date-fns";

// Compare dates
const isPast = isBefore(selectedDate, new Date());
const isFuture = isAfter(selectedDate, new Date());
const sameDay = isSameDay(date1, date2);

// Check special dates
const checkToday = isToday(selectedDate);
const checkYesterday = isYesterday(selectedDate);
```

**Parsing:**
```tsx
import { parseISO } from "date-fns";

// Parse ISO string from API
const date = parseISO("2025-09-01T14:30:00Z");
const displayDate = format(date, "do MMM yyyy"); // "1st Sep 2025"
```

### Date Formatting Examples

**Display workout date:**
```tsx
import { format } from "date-fns";

function WorkoutHeader({ workout }: WorkoutHeaderProps) {
  return (
    <div>
      <h2>Workout on {format(workout.date, "do MMM yyyy")}</h2>
      {/* Output: "Workout on 1st Sep 2025" */}
    </div>
  );
}
```

**Display relative date:**
```tsx
import { format, isToday, isYesterday } from "date-fns";

function formatWorkoutDate(date: Date): string {
  if (isToday(date)) return "Today";
  if (isYesterday(date)) return "Yesterday";
  return format(date, "do MMM yyyy");
}

// Usage
<p>{formatWorkoutDate(workout.date)}</p>
// Output: "Today" or "Yesterday" or "1st Sep 2025"
```

**Date range:**
```tsx
import { format } from "date-fns";

function DateRange({ startDate, endDate }: DateRangeProps) {
  return (
    <p>
      {format(startDate, "do MMM yyyy")} - {format(endDate, "do MMM yyyy")}
    </p>
  );
  // Output: "1st Sep 2025 - 30th Sep 2025"
}
```

### Date Input Handling

When using shadcn/ui Calendar component with date-fns:
```tsx
"use client";

import { useState } from "react";
import { format } from "date-fns";
import { Calendar } from "@/components/ui/calendar";
import { Button } from "@/components/ui/button";
import { Popover, PopoverContent, PopoverTrigger } from "@/components/ui/popover";

export function DatePicker() {
  const [date, setDate] = useState<Date>(new Date());

  return (
    <Popover>
      <PopoverTrigger asChild>
        <Button variant="outline">
          {format(date, "do MMM yyyy")}
        </Button>
      </PopoverTrigger>
      <PopoverContent>
        <Calendar
          mode="single"
          selected={date}
          onSelect={(newDate) => newDate && setDate(newDate)}
        />
      </PopoverContent>
    </Popover>
  );
}
```

## TypeScript Standards

### Type Safety
- **Strict mode enabled**: All code must pass TypeScript strict checks
- **Explicit prop types**: Always define interfaces for component props
- **No `any` types**: Use proper typing or `unknown` if truly dynamic
- **Export types when reusable**: Share types across files when needed

**Example:**
```tsx
// ✅ GOOD - Explicit interface
interface DatePickerProps {
  selectedDate: Date;
  onDateChange: (date: Date) => void;
}

export function DatePicker({ selectedDate, onDateChange }: DatePickerProps) {
  // ...
}

// ❌ BAD - No types
export function DatePicker({ selectedDate, onDateChange }) {
  // ...
}
```

### Readonly Props
Use `Readonly<>` for props that should not be mutated:
```tsx
export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  // ...
}
```

## Styling Standards

### Tailwind CSS v4
- **Utility-first approach**: Use Tailwind utility classes for all styling
- **No custom CSS files**: Avoid creating separate CSS modules unless absolutely necessary
- **Responsive design**: Use Tailwind's responsive prefixes (`sm:`, `md:`, `lg:`, etc.)
- **Dark mode support**: Use `dark:` prefix for dark mode variants

### Class Organization
Order classes logically for readability:
1. Layout (flex, grid, block)
2. Positioning (absolute, relative)
3. Sizing (w-, h-, p-, m-)
4. Typography (text-, font-)
5. Visual (bg-, border-, rounded-)
6. Interactive (hover:, focus:)
7. Responsive (sm:, md:, lg:)

**Example:**
```tsx
<div className="flex flex-col gap-4 p-6 bg-white border rounded-lg hover:shadow-md transition-shadow sm:flex-row">
```

### Tailwind Theme Variables
Use CSS custom properties defined in `src/app/globals.css`:
- `--background`: For page backgrounds
- `--foreground`: For text colors
- Access via `bg-background`, `text-foreground`

### Common Patterns
```tsx
// Buttons
<button className="px-6 py-3 bg-blue-600 text-white rounded-lg hover:bg-blue-700 transition-colors">

// Cards
<div className="border rounded-lg p-6 bg-white shadow-sm hover:shadow-md transition-shadow">

// Input fields
<input className="w-full px-4 py-2 border rounded-lg focus:outline-none focus:ring-2 focus:ring-blue-500" />

// Status badges
<span className="px-2 py-1 bg-green-100 text-green-700 rounded">Completed</span>
```

- **PascalCase**: `DatePicker`, `WorkoutCard`, `DashboardPage`

### Props Interfaces
- **Component name + Props**: `DatePickerProps`, `WorkoutCardProps`

### Event Handlers
- **Prefix with `handle`**: `handleDateChange`, `handleSubmit`, `handleClick`
- **Props prefix with `on`**: `onDateChange`, `onSubmit`, `onClick`

### State Variables
- **Descriptive names**: `selectedDate`, `workouts`, `loading`, `error`
- **Boolean prefix**: `isLoading`, `hasError`, `isVisible`

### Functions
- **camelCase**: `formatDate`, `calculateDuration`, `loadWorkouts`
- **Verb-based**: Start with action verbs

## Import Organization

### Order
1. React and Next.js imports
2. Third-party libraries
3. Internal components (using `@/` alias)
4. Types (using `type` keyword)
5. Styles (if any)

**Example:**
```tsx
import { useState, useEffect } from "react";
import Link from "next/link";
import { SignedIn, SignedOut } from "@clerk/nextjs";
import { Loader2, Dumbbell } from "lucide-react";
import { DatePicker } from "@/components/date-picker";
import { WorkoutCard } from "@/components/workout-card";
import type { WorkoutWithDetails } from "@/app/dashboard/actions";
```

### Path Aliases
- **Always use `@/` prefix**: `@/components/...`, `@/app/...`, `@/lib/...`
- **No relative imports**: Avoid `../../` paths
```tsx
// ✅ GOOD
import { DatePicker } from "@/components/date-picker";

// ❌ BAD
import { DatePicker } from "../../components/date-picker";
```

## State Management

### Local State
Use `useState` for component-local state:
```tsx
const [selectedDate, setSelectedDate] = useState<Date>(new Date());
const [loading, setLoading] = useState(true);
const [error, setError] = useState<string | null>(null);
```

### Type State Variables
Always provide type parameter for `useState`:
```tsx
// ✅ GOOD
const [workouts, setWorkouts] = useState<WorkoutWithDetails[]>([]);

// ❌ BAD
const [workouts, setWorkouts] = useState([]);
```

### Loading and Error States
Always handle loading and error states for async operations:
```tsx
const [loading, setLoading] = useState(true);
const [error, setError] = useState<string | null>(null);

try {
  setLoading(true);
  setError(null);
  // async operation
} catch (err) {
  setError(err instanceof Error ? err.message : "An error occurred");
} finally {
  setLoading(false);
}
```

## Accessibility

### Semantic HTML
- Use appropriate HTML elements (`button`, `nav`, `header`, `main`, `article`)
- Don't use `div` for clickable elements
```tsx
// ✅ GOOD
<button onClick={handleClick}>Click me</button>

// ❌ BAD
<div onClick={handleClick}>Click me</div>
```

### Labels and ARIA
- Associate labels with inputs using `htmlFor`
- Add `aria-*` attributes when needed
```tsx
<label htmlFor="date-picker" className="text-sm font-medium">
  Workout Date
</label>
<input id="date-picker" type="date" />
```

### Icons
- Use `aria-hidden` for decorative icons
- Provide text alternatives for meaningful icons
```tsx
<Calendar className="w-5 h-5 pointer-events-none" aria-hidden />
```
